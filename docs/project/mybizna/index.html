Mybizna — Commerce Platform for Small Businesses in Kenya

Overview

Mybizna is a multi-tenant commerce platform I build and run as the only engineer, live at mybizna.com and on the App Store and Google Play. A seller signs up, gets a website on their own domain, takes orders and bookings, and is paid to M-Pesa or a bank through Paystack split settlement. One deployment serves every seller: an Express and Mongoose API, a Next.js 16 dashboard with host-routed storefronts, a Flutter seller app, and Zod schemas shared as one OpenAPI spec. In its first 65 days: 3,043 commits, 554 reviewed pull requests, about 10,000 automated tests, 43 numbered design documents and more than 130 logged deploys. Every figure here was counted in the repository on 23 November 2026.

Challenges & Solutions

The problem that shapes everything is that one process serves every shop, so a query that forgets the shop does not return slightly wrong data: it returns another business's data. Convention had already failed at this once, on the restaurant platform, where a review found 37 unguarded endpoints. So the boundary is held in three places. One middleware resolves the shop from the signed-in user's memberships and nothing else reads the header; an ESLint rule fails any other read. The verified shop enters an AsyncLocalStorage context. A Mongoose plugin registered before any model hooks every query, aggregate, save and bulk write, and refuses a filter whose tenant names another shop; the only way past is a crossTenant call that must carry a reason string, so every exception is one grep away. The second problem was money. Ledger rows are never edited; a scheduler polls Paystack settlements and matches them to sales, payouts are verified against the processor's own records, and a failed settlement is a named state rather than a silent skip. The open items are written down too: a sale on a failed settlement still stalls the matcher, found on 20 November and not yet fixed.

Technical Achievements

  • Tenancy enforced by the runtime, not remembered by the author: a verified tenant context, a global Mongoose guard that refuses a filter naming another shop and refuses unscoped queries in staging, and a static ratchet in CI (193 sites across 37 models on 25 September, falling since)
  • Eleven architecture ratchets in CI, each with a baseline file that can only fall: tenancy, layering, structured logging, silent failures, native writes, secrets, typed environment, generated feature flags, country seam, one-off design values and helper copy length
  • Money that is append-only, then reconciled: Paystack split settlement to M-Pesa or bank, settlements polled and matched to sales, payouts verified against the processor, the money model written as a document before it was code
  • Observability before the second seller: one pino logger with ECS fields shared by API and web, a request id carried through every log line and returned in every response, liveness and readiness checks, graceful shutdown, Prometheus metrics behind a token
  • A security review of 135 findings, each with a status line a later reader can verify a fix against, and a launch review recording the delta after 293 further commits
  • Sellers' own domains through Cloudflare for SaaS with one Worker, because Railway caps custom domains at 20 per service and would have made every seller edit DNS on any move
  • Delivery priced by road distance from a private Valhalla router built from Kenya's OpenStreetMap roads, answering in under 1.5 seconds for a flat monthly cost; pins never reach a log
  • One door for every model call: Cloudflare AI Gateway, Claude Haiku first with the feature's OpenAI model as fallback, a budget per prompt, and a help assistant that answers only from written articles and prepares changes the seller confirms
  • Shipped on three surfaces: 104 API models, 118 web pages and 61 Flutter screens, with about 9,000 API test cases across 680 files and 1,600 on the web
