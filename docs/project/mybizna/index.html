Mybizna: one deployment, every seller, real money

A commerce platform for small businesses in Kenya. A seller signs up, gets a website on their own domain, takes orders and bookings, and is paid to M-Pesa or a bank. I am the only engineer. This page is about the decisions that made it safe to ship daily.

Decisions that mattered

Each one names the problem, what I chose, and where a reviewer can check it.

1. The tenant is a property of the actor, and the runtime refuses anything else

One process serves every shop, so a query that forgets the shop does not return slightly wrong data. It returns another business's data. Convention had failed at this once before, on the restaurant platform, where a review found 37 unguarded endpoints. So here the boundary is held in three places.

One middleware resolves the shop from the signed-in user's memberships and nothing else reads the header; an ESLint rule fails any other read. The verified shop enters an AsyncLocalStorage context. A Mongoose plugin registered before any model hooks every query, aggregate, save and bulk write: inside a context it refuses a filter whose tenant names another shop, outside one it refuses an unscoped query in staging and logs it in production until seven quiet days pass. The only way past is .crossTenant('reason'), and the reason is a string so every exception is one grep away.

Evidence: docs/14 §1, models/plugins/tenantScoped.ts, tests/unit/tenantIsolation.test.ts, the ratchet in scripts/arch/audit-tenant-scoping.js (193 sites across 37 models on 25 September, falling since).

2. Rules get a check in CI that can only get stricter

A standards document nobody runs is a wish. Each rule here has an audit script with a baseline file: tenancy, layering (routes never touch models), structured logging, silent failures, native writes that skip the guard, secrets in the tree, environment variables typed in one place, feature flags generated from one registry, country-specific words outside the locale seam, one-off design values, and helper copy over eight words. A pull request may lower a count or hold it. The build fails if a count rises. The numbers trend down because that is the only direction allowed.

Evidence: pnpm api lint:arch in .github/workflows/ci.yml; the eleven .*-baseline.json files; docs/14 §11.

3. Money is append-only, then reconciled against the processor

Sellers are paid through Paystack split settlement: the buyer pays once, the platform fee and the seller's share are divided at the processor, and the seller's share lands in their M-Pesa or bank. Ledger rows are never edited.

A scheduler polls settlements and matches them to sales; payouts are verified against the processor's own records; a failed settlement is a named state, not a silent skip. The money model (fee ladder, split timing, what the seller sees on each screen) is a document before it is code, and the first live payout was reconciled by hand against it. The open items are written down too: a sale on a failed settlement still stalls the matcher, found 20 November, not yet fixed.

Evidence: docs/13 money model, docs/16 Paystack review, docs/30 §2.8 append-only records, the settlement and payout schedulers under services/.

4. Observability was built before the second seller, not after the first outage

One logger on pino with ECS fields, shared by API and web. A request id minted at the edge, carried through every log line and returned in every response and error body, so a seller's screenshot leads to the exact trace. Liveness and readiness endpoints that check the database, graceful shutdown that drains in-flight requests, Prometheus metrics behind a token, and an access log. The audit that led to it listed nine gaps; each has a finding number and a status.

Evidence: docs/30 production readiness, packages/logger, /api/health/live, /api/health/ready, /metrics.

5. A security review with a status line per finding

A full review of authentication, tenancy, payments, the public storefront, uploads, the Worker, the app, schedulers and secrets produced 135 findings. Each carries a status a later reader can verify a fix against, and the launch review three weeks later recorded the delta after 293 commits. Dependency advisories are triaged by whether the vulnerable path is reachable, not by count: of seven in one Next.js upgrade, two applied.

Evidence: docs/25 security review, docs/40 help-assistant security review, the Next.js 16.4.6 upgrade PR.

6. Sellers' own domains through Cloudflare for SaaS, with one Worker

Railway caps custom domains at 20 per service and gives each a different CNAME target, which would have meant every seller editing DNS if we ever moved. Instead a seller points a CNAME at a stable name under our zone, Cloudflare issues the certificate, and a Worker forwards to an origin host Railway knows, caching only hashed static files. Capacity is a number with a warning at 80 percent.

Evidence: docs/19 custom domains, infra/cloudflare/.

7. Road distance from our own router, so a pin never leaves the house

Delivery priced by distance needs road kilometres between two pins. Google's Distance Matrix costs per call and sees both addresses. A private Valhalla service on Railway builds Kenya's OpenStreetMap roads once and answers in under 1.5 seconds for a flat monthly cost; past the timeout, the straight line times 1.3 prices the order and the record says which method it used. The pins never reach a log.

Evidence: docs/26 delivery workflow, services/routing/valhalla.ts, infra/railway/Dockerfile.routing.

8. One door for every model call

Product descriptions, the help assistant, photo judgement and listing moderation all go through one gateway: Cloudflare AI Gateway in front, Claude Haiku first, the feature's OpenAI model as the fallback, a budget per prompt, and an alert when a feature's failure rate climbs. The help assistant answers only from written articles, builds its cards on the server, and prepares changes the seller confirms rather than applying them.

Evidence: docs/36 AI gateway, docs/39 help assistant, docs/40 its security review.

What I would do differently

Build the declared database indexes by migration from day one; Mongoose's auto-indexing was off and several declared indexes were never created in production. Put the four-shard API test suite in CI before the suite reached the size that needs sharding. Write the country seam before the first Kenya-specific string, not after a thousand of them.
